How DakGhar Works

A simple explanation of the notification delivery system.

1. Message enters the system

The user submits an email or SMS using the Send screen. FastAPI validates the data and saves it in SQLite with pending status.

2. Worker checks the outbox

The worker runs separately in the background. It checks for messages that are ready to be processed.

3. Engine chooses a provider

The engine chooses a healthy provider for the message's channel. Each channel has a primary and a backup provider.

4. Provider tries delivery

The mock provider simulates success, temporary failure or permanent failure. It does not send real emails or SMS.

5. Retry and failover

Temporary errors can be retried after 2, 4 and 8 seconds. If a provider fails repeatedly, the circuit breaker temporarily removes it from use.

6. Attempt history is saved

Each delivery attempt is stored in the attempts table. Successful messages are also added to the fake inbox.

Important concepts

Outbox

The database table where accepted messages are stored.

Retry

Trying to deliver a message again after a temporary failure.

Failover

Switching to another provider when the previous provider fails.

Circuit Breaker

Temporarily avoiding a provider after repeated failures.
